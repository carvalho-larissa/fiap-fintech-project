# T07 — Massa de dados de teste

| Campo | Valor |
|---|---|
| Status | ✅ Concluída |
| Tamanho | M |
| Depende de | T06 |
| Bloqueia | T13 |
| Requisitos | Suporte a RF-10 a RF-15 |

## Objetivo
Carregar dados **determinísticos** que cubram os caminhos normais e os casos de borda de todas as consultas, com resultados esperados conhecidos **antes** de executar os testes.

## Escopo
**Inclui:** usuários, contas, categorias, receitas, gastos, investimentos (+ 1 meta/dívida opcional para realismo).
**Não inclui:** volume para teste de performance.

## Especificação
Arquivo `database/dml/02-seed.sql`, com IDs **explícitos** (permitido por `BY DEFAULT`, D-02) e `COMMIT` ao final. Ao fim do script, reajustar as identities: `ALTER TABLE … MODIFY id_x GENERATED BY DEFAULT ON NULL AS IDENTITY (START WITH LIMIT VALUE)`.

Cenários obrigatórios:

| Usuário | Situação | Serve para |
|---|---|---|
| U1 — Larissa (dados do `Main.java`) | 3+ gastos em datas diferentes **e 2 gastos na mesma data**; 3+ investimentos, incluindo 2 na mesma data | Ordenação, desempate D-08, dashboard completo |
| U2 | Gastos, **nenhum** investimento | Dashboard com investimento nulo (D-12) |
| U3 | Investimentos, **nenhum** gasto | Dashboard com gasto nulo (D-12) |
| U4 | Sem movimentação | Dashboard só com dados do usuário |
| (ID 999) | Inexistente | Consultas devem retornar 0 linhas |

Complementos:
- Categorias: ao menos 3 de `GASTO` (Moradia, Alimentação, Transporte) e 2 de `RECEITA` (Salário, Freelance) — alinhadas ao protótipo `frontend/index.html`.
- Valores coerentes com o front (ex.: salário 5.800,00; aluguel 1.850,00).
- **Isolamento**: pelo menos um gasto de U2 com data **mais recente** que o último gasto de U1 → prova que o dashboard/ordenação filtra por usuário.

Documento de oráculo: `database/testes/resultados-esperados.md` com, para cada consulta e usuário, as linhas exatas esperadas (ordem incluída).

## Critérios de aceitação
- [ ] Script roda sem erro após T06 e é reexecutável (após `00` + `01`)
- [ ] Todos os cenários da tabela acima presentes
- [ ] `resultados-esperados.md` escrito **antes** da execução dos testes (T13)
- [ ] Nenhum dado pessoal real (e-mails `@exemplo.com`, senhas como hash fictício)
